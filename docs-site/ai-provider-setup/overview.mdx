---
title: "选择 AI 提供商"
description: "创建工作流、后处理脚本或扫描前，先配置一种受支持的模型提供商。"
---

open·kritt 需要**一种** AI 访问方式。你可以配置多种方式，并在每次运行时选择其中一种；开始使用时，只需确保其中一个提供商可用。

| 提供商 | 访问方式 | 模型输入方式 |
| --- | --- | --- |
| **Codex** | ChatGPT/Codex 登录或 OpenAI Platform 密钥 | 按账户显示可用模型 |
| **Claude** | Claude 订阅登录或 `ANTHROPIC_API_KEY` | 订阅别名或按账户显示可用模型 |
| **DeepSeek** | `DEEPSEEK_API_KEY` | 可搜索的认证模型目录 |
| **OpenRouter** | `OPENROUTER_API_KEY` | 可搜索的认证模型目录，也支持输入准确的模型 ID |
| **xAI** | Grok 设备登录或 `XAI_API_KEY` | 使用密钥时显示可搜索的认证模型目录，也支持输入准确的模型 ID |

也可以在应用里的**自定义 LLM**页面，给 Codex 或 Claude Code 接一个自己的接口。Codex 只使用 OpenAI Responses：当前固定的 Codex 0.145.0 会直接拒绝 Chat Completions，本应用也不会做协议转换。Claude Code 使用 Anthropic Messages。这只替换模型接口，不改变运行框架本身。Grok Build 继续使用上面的 xAI 账户。

## 提供商可见性与 API 检查

新的浏览器配置会显示所有提供商。扫描和草稿生成选择器会列出 **Codex**、**Claude Code**、**DeepSeek**、**OpenRouter** 和 **xAI**；没有账户的提供商仍会显示，但无法选择。
你可以在账户页面或提供商选择器旁使用**显示或隐藏提供商**来自定义列表。现有浏览器偏好会保留，因此如果之前隐藏了提供商，需要手动重新启用。隐藏不会删除账户或更改已保存的选择；已选中的提供商仍会在其选择器中显示。

[DeepSeek](/ai-provider-setup/deepseek) 使用实时模型目录，并在扫描和草稿生成中使用 Codex 运行框架。账户页面还提供简短的文本 API 检查。

## 常见配置流程

<Steps>
  <Step title="打开设置">
    在仓库根目录运行：

    ```bash
    ./kritt setup
    ```
  </Step>
  <Step title="选择一种访问方式">
    选择 **Codex 登录**、**OpenAI API 密钥**、**Codex API 密钥**、**Anthropic API 密钥**、**DeepSeek API 密钥**、**OpenRouter API 密钥**或 **xAI API 密钥**。凭据获取方式请参阅上方对应的提供商指南。命令行工具可配置 API 密钥和 Codex 登录；Claude 和 xAI 设备登录，以及 DeepSeek/OpenRouter/xAI 密钥管理，也可以在正在运行的应用的**账户**页面中完成。
  </Step>
  <Step title="启动或重建服务栈">
    ```bash
    ./kritt start
    ```

    如果 open·kritt 已在运行，请先按 Ctrl+C 停止前台服务栈。Compose 重建容器前，现有容器不会收到新修改的 `.env` 值。
  </Step>
  <Step title="验证提供商配置">
    再次运行 `./kritt setup`，确认所选方式显示为已配置。工作流生成器、后处理脚本生成器和新建扫描表单会启用 open·kritt 检测为已配置的提供商；其他可见提供商会链接到账户页面。
  </Step>
</Steps>

## 凭据处理

通过命令行工具配置的 API 密钥会写入仓库的 `.env` 文件。Codex 登录信息保存在 `ENGINE_CODEX_ACCOUNTS_HOST` 指定的位置（默认为 `./.data/codex-accounts`）；Claude 登录信息保存在 `ENGINE_CLAUDE_HOME` 指定的位置（默认为 `./.data/claude`）；Grok/xAI 登录信息保存在 `ENGINE_GROK_HOME_HOST` / `ENGINE_GROK_ACCOUNTS_HOST` 指定的位置（默认为 `./.data/grok` 和 `./.data/grok-accounts`）。账户页面会将 Codex/Claude/xAI 账户路径及 DeepSeek、OpenRouter 和 xAI 密钥与 `.env` 保持同步，并将这些密钥镜像到 `.data/engine/credentials`，以便正在运行的服务立即读取更改。`.env` 和 `.data/` 均已加入 Git 忽略规则。

<Warning>
  请将 `.env`、`./.data/codex`、`./.data/codex-accounts`、`./.data/claude`、`./.data/grok`、`./.data/grok-accounts` 和引擎凭据目录视为机密信息。切勿将其提交到仓库、粘贴到议题中或分享给其他用户。凭据一旦泄露，请立即撤销并更换。
</Warning>

后端可以私下写入 `.env` 和提供商存储，以便账户页面持久化添加和删除操作，但 API 不会返回机密值。引擎启动模型运行框架时会接收实际凭据。

<Note>
  `GITHUB_TOKEN` 不是 AI 提供商凭据。它是可选项，仅在克隆私有 GitHub 代码库或依赖项时需要。
</Note>
