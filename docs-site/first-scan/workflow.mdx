**工作流**是一种可复用的扫描方案：由引擎按序执行的一组提示词**步骤**构成，每一步的输出都会传给下一步。其核心思路是将漏洞搜寻拆分为小而聚焦的任务，而不是写成一个庞大的提示词。

<Tip>
  open·kritt 还会安装[基础内置工作流](/workflows/built-in-workflows)。你可以直接在扫描中选择一个，也可以先查看再创建自己的工作流。本教程会带你创建一个小型工作流，了解各部分如何协作。
</Tip>
## 开始之前

<Info>
  创建第一个工作流前，请先完成[安装和设置](/getting-started/installation-and-setup)。
</Info>

## 创建工作流

打开**工作流 → 新建工作流**。你可以创建空白工作流、复制现有工作流，或选择**使用 AI 生成**。

### 使用 AI 生成草稿

描述你需要的安全研究流程，包括：

- 目标和重要的排除项；
- 各阶段及其顺序；
- 每个阶段应生成的内容；
- 哪些位置需要拆分为并行的同级步骤；
- 扫描使用者需要通过 `extra` 变量提供的值。

然后选择已配置的提供商、模型、思考强度和运行框架。引擎会先生成并验证完整草稿，再在常规工作流构建器中打开。请检查名称、提示词、变量、深度行为和输出结构，然后手动保存。生成过程不会自动创建工作流。

<Note>
  生成的草稿遵循与手动创建工作流相同的规则。引用必须指向内置项、`extra` 值或前序步骤的输出；末尾深度必须输出所有必需的发现项字段，并使用对应类型。
</Note>

### 手动构建

选择**空白工作流**，填写名称和简短说明，然后开始添加步骤。

<Frame caption="工作流构建器：按深度分组步骤，并实时校验提示词。">
  <img src="/images/workflow-builder.png" alt="open·kritt 工作流构建器" />
</Frame>

每个步骤包含两部分：

- **提示词内容** — 发送给智能体的指令，可包含 `{{variable}}` 占位符。
- **输出结构** — 此步骤必须输出的字段及其类型（`string`、`number`、`boolean`、`array`、`object`）。

## 按深度组织步骤

步骤按**深度**组织。深度 0 是入口，只运行一次。更深层级会处理上一层生成的结果。

最简单的两层结构如下：

1. **深度 0 — 枚举。** 让智能体列出候选入口（例如所有 HTTP 路由）。将其标记为**多输出**，以便生成多条结果。
2. **深度 1 — 分析。** 针对深度 0 中的每个入口，分别提出聚焦问题。可以直接引用深度 0 的字段，例如 `{{entrypoint}}`。

最后一个（最深层）步骤比较特殊：它必须输出固定的**发现项结构**，以保证结果一致、可比较。构建器会标出此要求；末尾步骤声明所有必需字段后才能保存。

<Note>
  构建器会在输入时进行校验。**引用字段**有效时显示为绿色，无效时显示为红色；**可用字段**列表会展示可插入的内置字段和前序深度的输出。
</Note>

## 保存工作流

当提示显示**“工作流有效，可以保存”**时，点击**保存更改**。此工作流即可供扫描任务复用。
