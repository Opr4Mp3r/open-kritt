open·kritt 使用 Docker Compose 在本地运行。仓库内附带 `./kritt` 交互式命令行工具，可创建环境文件、引导配置模型访问并启动服务栈。无需通过 npm 安装该工具。

## 前置条件

- [Docker Desktop](https://www.docker.com/products/docker-desktop/), or Docker Engine with
  the Docker Compose plugin, version 2.13.0 or newer (`docker compose version`)
- Git
- Node.js 20 or newer for the repository-local CLI

手动配置 Docker 时不需要主机安装 Node.js。对于默认软件源仍提供 Node 16 或 18 的发行版，这一点很有用。

### 已测试的 Linux 环境

完整源码构建、五个常驻服务（以及一次性运行器镜像辅助服务）和扫描启动，均已在以下 Linux 环境组合中验证：

| Distribution | x86_64 | ARM64 | Startup paths checked |
| --- | --- | --- | --- |
| Ubuntu 24.04 | Yes | Yes | `./kritt start`, manual Compose |
| Debian 12 | Yes | Yes | manual Compose, development overlay |
| Rocky Linux 9 | Yes | Yes | `./kritt start`, manual Compose with SELinux Enforcing |

Docker Desktop 仍是 macOS/Windows 的常规开发方式，但不属于上述 Linux 云端测试矩阵。镜像会针对主机架构构建，因此在已测试的 ARM64 主机上无需模拟 amd64。

### 安装 Node.js 20 或更高版本

运行命令行工具前，请先检查版本：

```bash
node --version
```

在 Ubuntu 24.04 或 Debian 12 上，发行版默认提供的版本可能低于 Node 20。可以使用 NodeSource 22.x 软件源安装：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
node --version
```

在 Rocky Linux 9 上，请选择当前的 AppStream，而不要安装默认流：

```bash
sudo dnf module reset -y nodejs
sudo dnf module enable -y nodejs:20
sudo dnf install -y nodejs
node --version
```

如果你的发行版没有合适的软件流，请使用 Node 版本管理器，或跳过命令行工具并参照[手动配置 Docker](#manual-docker-setup)。

在 Linux 上，请先确认普通用户可以访问 Docker。以下两条命令都必须成功：

```bash
docker info >/dev/null
docker compose version
```

### Docker 预检

`./kritt start` 和两种交互式登录都会在启动容器前检查 Docker；如果检查失败，会停止操作并说明原因：

| 问题 | 处理方式 |
| --- | --- |
| 检测到的问题 | 处理方式 |
| Docker 守护进程无法访问 | 启动 Docker Desktop 或 `docker` 服务。如果安装了多个 Docker，请确认 `docker context ls` 选择的是正在运行的实例。 |
| Docker Compose 插件不可用 | 安装 Compose 插件或 Docker Desktop，并确认 `docker compose version` 可以正常执行。 |
| Docker Compose 版本过旧 | 更新 Docker。交互式登录会运行 `docker compose run --build`，需要 Compose 2.13.0 或更高版本。 |
| 无法确认 Docker Compose 版本 | 在本地执行 `docker compose version` 检查，并更新 Docker Compose。 |
| Docker 诊断在 30 秒内未完成 | 在本地检查 Docker 和所选 context，然后重试。此超时仅适用于预检。 |
| Docker Compose 无法读取此项目 | 更新 Docker，或在本地检查 `docker-compose.yml` 和 `.env`。 |

启动提示不会显示原始诊断输出或配置值。交互式登录、镜像构建和应用启动均不受诊断超时限制。

在加入此项检查之前，Docker 未启动或版本过旧时只会表现为登录未能保存任何内容。

如果 Docker 需要 `sudo` 才能运行，请先配置[非 root 用户的 Docker 访问权限](https://docs.docker.com/engine/install/linux-postinstall/)，或使用[rootless Docker](https://docs.docker.com/engine/security/rootless/)，再运行 open·kritt 命令行工具。

<Warning>
  在 Linux 上，请以普通用户身份运行 `./kritt`，不要使用 `sudo`。Codex 交互式登录和命令行导入会保留主机用户对 `auth.json` 的所有权。如果旧版本以 `root` 身份创建了凭据，请参阅 [Linux 文件所有权和权限](/ai-provider-setup/codex#linux-ownership-and-permissions)。
</Warning>

<Warning>
  可使用工具的扫描智能体会以 root 身份在一次性嵌套容器中运行，并拥有可写的代码库副本和直接互联网访问权限。引擎会控制 Docker 守护进程来创建这些任务。扫描不可信目标时，请使用专用 Docker 主机或虚拟机；不要在运行其他敏感工作负载的主机上部署 open·kritt。
</Warning>

## 安装并启动

<Steps>
  <Step title="克隆代码库">
    ```bash
    git clone https://github.com/Kritt-ai/open-kritt && cd open-kritt
    ```
  </Step>
  <Step title="打开命令行工具">
    ```bash
    ./kritt
    ```
    使用方向键选择**设置**，按 Enter 并根据提示操作。如果 `.env` 不存在，命令行工具会根据 `.env.example` 创建该文件。
  </Step>
  <Step title="配置模型访问">
    选择一种模型访问方式。推荐使用 Codex 交互式登录，也可以使用提供商 API 密钥。账户、密钥、计费和验证步骤请参阅 [AI 提供商配置指南](/ai-provider-setup/overview)。GitHub 令牌为可选项，仅在访问私有 GitHub 仓库时需要。
  </Step>
  <Step title="启动 open·kritt">
    在菜单中选择**启动**，或运行：
    ```bash
    ./kritt start
    ```
    该命令会运行 `docker compose up --build` 并持续显示服务栈输出。按 Ctrl+C 停止。
  </Step>
</Steps>

启动后，打开 [http://localhost:5173](http://localhost:5173)。后端健康检查接口为 [http://localhost:3002/api/health](http://localhost:3002/api/health)。如果当前机器没有浏览器，请保持服务栈运行，并在另一个终端使用 [`./kritt-headless`](/getting-started/headless-cli)。

## 配置模型访问

创建扫描时需要配置以下**任意一种**方式：

| 选项 | 适用场景 |
| --- | --- |
| [**Codex login**](/ai-provider-setup/codex) (recommended) | Use eligible ChatGPT/Codex subscription access through the guided device flow. |
| [`OPENAI_API_KEY`](/ai-provider-setup/codex) | Use an OpenAI Platform API key with the Codex harness. |
| [`CODEX_API_KEY`](/ai-provider-setup/codex) | Use the same kind of OpenAI Platform key as a direct Codex execution override. |
| [`ANTHROPIC_API_KEY`](/ai-provider-setup/claude-code) | Use Claude Code with Anthropic API billing. |
| [`OPENROUTER_API_KEY`](/ai-provider-setup/openrouter) | Route a compatible model through OpenRouter. |

`GITHUB_TOKEN` 与模型访问方式无关。仅当扫描需要克隆私有 GitHub 代码库或依赖项时才需配置。

设置页面会显示已配置的选项，并允许你设置、替换、取消设置或查看相关说明；它不会输出凭据内容。

## 命令行指令

| 命令 | 用途 |
| --- | --- |
| `./kritt` | 打开全屏交互菜单。使用方向键导航、Enter 选择，按 Esc 或 Ctrl+C 退出。 |
| `./kritt setup` | 必要时创建 `.env`，并配置模型访问方式或可选的 GitHub 令牌。 |
| `./kritt start` | 检查设置和 Docker，然后运行 `docker compose up --build`。按 Ctrl+C 停止前台服务栈。 |
| `./kritt help` | 显示命令帮助。使用 `./kritt help setup` 或 `./kritt help start` 查看具体命令的说明。 |
| `./kritt-headless` | 在没有网页界面的情况下操作运行中的服务栈：导入资源、创建和检查扫描、配置设置并导出结果。 |
| `./kritt-headless help` | 显示无界面交互模式和命令模式的用法。 |

## 手动配置 Docker

推荐使用命令行工具。若要改用 API 密钥手动配置服务栈：

```bash
cp .env.example .env
chmod 600 .env
# Set one provider credential in .env: OPENAI_API_KEY, CODEX_API_KEY,
# ANTHROPIC_API_KEY, or OPENROUTER_API_KEY.
mkdir -p .data/codex
chmod 700 .data/codex
docker compose up --build
```

## 可选的演示数据

服务栈启动后，可以加载示例工作流、扫描和发现项，以便了解界面：

```bash
docker compose exec backend npm run seed
```

演示数据采用增量、幂等方式导入。它会保留现有的工作流、扫描、发现项、后处理脚本和分诊数据，并跳过已经存在的演示记录。
